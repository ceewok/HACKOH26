# Hardened Blueprint diagram-generation boundary

Task 5 now rejects the previously reported `flowchart TD this is prose` response before returning 200, and the backend test covers that exact declaration-prefixed case. The local Express transport now converts syntactically malformed JSON bytes into the documented `{ error: { code: "bad_request", message: "Invalid JSON body" } }` 400 envelope, with a real loopback request exercising the parser boundary. Bedrock still receives JSON-encoded design data through Converse with an explicit 700-token cap and adaptive retries, while the Studio lazy-loads Mermaid under strict security and only replaces a preview after a render succeeds. **Watch for:** **confirmed** the new regex accepts other parser-invalid declaration-prefixed Mermaid source, so the service can still return a false 200; **confirmed** the new public Bedrock endpoint runs under an execution role allowed to invoke every Bedrock model.

**Verdict**: NEEDS_CHANGES

## High-level view

The handler uses a narrow line-oriented grammar as the boundary between untrusted model text and the browser. That blocks the exact prose case added after QA, but the grammar allows unbalanced nested delimiters inside node labels that Mermaid rejects. The existing client-side failure path preserves the last successful SVG, but it cannot correct a successful API response that violates the documented valid-Mermaid contract.

The Bedrock request shape follows the Converse boundary and avoids credential disclosure in its 502 responses. The deployed route remains unauthenticated by contract, while its new Lambda policy grants `bedrock:InvokeModel` against `*`; this combines a public cost-bearing API with permission broader than the configured model needs.

The local and Lambda transports now agree on malformed JSON. The raw-byte test proves the Express JSON parser no longer bypasses the common structured-error contract.

## The Mermaid gate is not yet equivalent to the renderer grammar

**confirmed** the new `SIMPLE_EDGE` validation in `backend/src/handlers/ai.ts` rejects the prior `flowchart TD this is prose` case and the corresponding `ai.test.ts` assertion expects the generic 502. It nevertheless allows `A[[x]` as the start node because the text inside an optional square-bracket label may itself contain `[`. `normalizeMermaid("flowchart TD\nA[[x] --> B")` returns that source, and `createAiHandlers` returns `{ status: 200, body: { mermaid: ... } }`.

Mermaid 11.4.1 rejects the same source with a parse error. The result crosses the model-output trust boundary as an asserted valid diagram and becomes a client-side render failure instead. The Studio retains a last-good preview when that happens, and the frontend test covers a renderer rejection, but the API contract still promises a valid flowchart for every 200. Reject parser-invalid source before the response and retain the existing generic unusable-output 502.

## Bedrock invocation is bounded but the new public capability is broadly authorized

The Converse call uses `BedrockRuntimeClient`, an explicit `maxTokens: 700`, and adaptive retries, matching the SDK's current invocation guidance. Generator failures and unusable text become generic 502 responses, so AWS credential and service details are not reflected to clients. The system prompt also identifies submitted JSON as data rather than instructions, and the server's allowlist limits what reaches Mermaid.

**confirmed** `backend/template.yaml` adds an execution-role statement with `bedrock:InvokeModel` and `Resource: "*"`. The public route currently chooses its configured model, but this role can invoke any Bedrock model if its model parameter or another handler changes. Restrict the statement to approved foundation-model or inference-profile ARNs, constrain the parameter accordingly, and add an API-level quota, throttling, or authenticated boundary appropriate for a non-demo deployment.

## Local malformed JSON now follows the shared error contract

`createLocalApp` installs error middleware immediately after `express.json()`. It converts the parser's `SyntaxError` into the same `bad_request` envelope Lambda returns for a failed `JSON.parse`. `local-server.test.ts` sends the incomplete raw body `{"problemId":` over a loopback `fetch` and verifies both the 400 status and full JSON response, so this transport boundary is covered rather than inferred from handler tests.

The coordinator and product specification now describe the implemented 400/502 behavior, conservative server-side Mermaid subset, blocked live Bedrock smoke, lazy loading, and last-good-preview behavior. The underlying backend suite reports 17 passing tests; the frontend suite reports 13 passing tests; both typechecks and production builds pass. Not tested: a live Bedrock invocation, which the documentation accurately marks as blocked on credentials and enabled model access.
